# Creative Direction

## JET FERRARI Portfolio

### Version 1.0

## Purpose

The portfolio should present Jet Ferrari as a professional working at the intersection of creative problem solving, product thinking, systems thinking, rapid prototyping, AI directed engineering and technical discipline.

The website itself should function as evidence of that combination.

The central idea is:

> **Ambiguity becomes structure. Structure becomes product.**

The visitor should initially encounter something that feels fragmented and difficult to interpret. Through interaction, that apparent disorder gradually reveals relationships, systems, products and meaning.

The transformation is the message.

## Creative Thesis

The site should sit between three visual worlds.

### Editorial Art

Large negative space, elegant typography, deliberate composition and visual silence.

### Scientific Illustration

Fine lines, annotations, structures, diagrams and systems.

### Contemporary Software

Data, code, states, flows, architecture and interaction.

None of these should dominate completely.

The result should feel neither like an art portfolio nor like a conventional developer portfolio.

## Reference Language

The watercolor illustrations previously created by Jet serve as mood references only.

The useful characteristics are:

* generous negative space
* fine drawing
* selective color
* subtle materiality
* restrained watercolor
* editorial composition
* balance between precision and organic form

Their botanical subjects and layouts should not be copied.

The site should derive a new visual vocabulary from the same artistic sensitivity.

## Core Visual Metaphor

The interface begins with apparently unrelated elements:

* numbers
* symbols
* mathematical notation
* synthetic code
* technical words
* points
* curves
* diagram fragments
* lines
* watercolor traces

At first these elements appear independent.

They move slowly.

Some overlap.

Some form temporary relationships.

When the visitor interacts, fragments begin to align.

Lines find nodes.

Numbers become diagrams.

Code becomes structure.

Pigment becomes form.

Chaos becomes intention.

## Visual Personality

The experience should feel:

* intelligent
* experimental
* controlled
* poetic
* precise
* organic
* quiet

The goal is sophisticated curiosity, not visual overload.

## Surface

The base surface should resemble high quality watercolor paper.

It should be:

* warm white
* very lightly textured
* contemporary
* clean
* almost imperceptibly fibrous

Avoid distressed parchment, aged paper or vintage scrapbook aesthetics.

## Color Direction

The global interface remains mostly neutral.

Base tones:

* warm paper white
* graphite
* ink grey
* muted sepia

### Pulsar

Suggested family:

* indigo
* mineral blue
* graphite
* diluted blue grey
* restrained violet

Pulsar should feel analytical and cerebral.

### RestaurantZero

Suggested family:

* terracotta
* muted ochre
* olive
* warm brown
* restrained amber

RestaurantZero should feel more tangible and operational.

## Typography

Use three typographic roles.

### Editorial Serif

For conceptual statements, selected titles and moments of visual pause.

### Contemporary Sans Serif

For navigation, descriptions, interface labels and technical explanation.

### Restrained Monospace

For synthetic code, formulas, numbers and technical fragments.

The monospace should remain secondary.

## Hero

The first viewport should feel almost empty.

At the center sits a living visual cluster containing:

* data fragments
* technical language
* numbers
* formulas
* synthetic code
* diagram pieces
* fine lines
* controlled watercolor marks

Near the cluster:

# JET FERRARI

### AI Assisted Product Engineer

Suggested supporting statement:

> I turn ambiguous ideas into structured, testable software through creative problem solving, rapid prototyping and AI directed engineering.

## Hero Interaction

The hero should have three primary states.

### Ambient

Fragments move very slowly.

No fast particles.

No decorative spinning.

The cluster should feel alive rather than animated.

### Attraction

When the cursor approaches a region, nearby fragments react.

Some connections become clearer.

Certain elements begin to group.

Watercolor can subtly propagate behind related elements.

### Structure

When the user focuses on a meaningful cluster, apparent chaos becomes a recognizable structure.

Examples:

```text
LLM
 |
 v
Structured Output
 |
 v
Validation
 |
 v
Domain Rule
```

or

```text
Catalog
 |
 v
Cart
 |
 v
Pricing
 |
 v
Order
```

All visible technical material must remain synthetic.

## Profile Section

Avoid conventional resume cards.

Use concise conceptual blocks:

### What I Do

Transform product problems into working software using architecture, experimentation and AI assisted implementation.

### How I Think

Decompose uncertainty, identify constraints, explore resources and find practical paths toward testable solutions.

### How I Build

Move from specification to prototype, then from prototype to validated system through agents, tests and review.

## Projects

Projects should emerge from the visual language of the page instead of appearing as generic cards.

### Pulsar

Creative metaphor:

**Fluid intelligence meeting structural boundaries.**

Possible visual behavior:

* branching possibilities
* uncertain signals
* structured nodes
* validation gates
* paths that terminate
* paths that become accepted
* watercolor diffusion interrupted by precise graphite lines

The public site must not expose internal prompts, schemas, datasets, financial rules or proprietary implementation.

### RestaurantZero

Creative metaphor:

**Individual pieces becoming an operational system.**

Possible visual behavior:

* catalog fragments
* cart state
* pricing relationships
* order flow
* persistence references
* modular nodes organizing into architecture

The public site must not expose detailed database structure or proprietary business logic.

## Motion Principles

### Slow by Default

Ambient motion should be subtle.

### Fast Only in Response

Direct interaction can create faster local movement.

### Organic Acceleration

Motion should resemble pigment spreading, magnetic attraction, ink following fibers or objects finding equilibrium.

### Meaningful Transformation

Animation must communicate state change.

Avoid motion that exists only as decoration.

## Watercolor Motion

Prefer:

* masks revealing real watercolor textures
* transparency variation
* subtle edge bleeding
* layered pigment
* controlled displacement
* SVG masking

Avoid excessive simulated watercolor video loops.

## Microinteractions

Possible details:

* ink stroke link underline
* restrained watercolor wash on button hover
* editorial annotation labels
* subtle pigment diffusion during project transitions
* cursor proximity affecting nearby fragments

All interactions must remain usable without animation.

## Navigation

Desktop:

* Home
* Profile
* Projects
* Process
* Contact

Navigation should be visually quiet.

Avoid glassmorphism, floating navigation containers and neon active states.

## Content Hierarchy

Each section should answer one question.

### Hero

Who is this person?

### Profile

How does he think?

### Projects

What has he built?

### Process

How does he build?

### Contact

How can I reach him?

## Accessibility

The concept cannot depend only on mouse hover.

Desktop can use pointer proximity.

Mobile should use scroll and tap states.

Support reduced motion.

Maintain readable contrast over watercolor areas.

The information must remain understandable without animation.

## Performance

The artistic concept does not justify poor performance.

Avoid:

* giant autoplay video
* unnecessary heavy WebGL
* permanent physics simulations
* excessive transparent raster assets
* heavy animation dependencies without clear value

Performance is part of the engineering demonstration.

## Responsive Direction

Desktop can emphasize spatial interaction.

Mobile should emphasize sequence.

The mobile experience should simplify the visual system rather than compress the desktop composition.

## Explicit Anti Patterns

Do not turn the site into:

* a dark developer portfolio
* cyberpunk UI
* hacker terminal aesthetic
* neon AI imagery
* startup landing page
* SaaS dashboard
* technology badge wall
* glassmorphism showcase
* generic particle background
* gaming interface
* botanical portfolio copied from prior artwork
* art portfolio disconnected from engineering

## Key Principle

> **Complexity should reveal structure, not decoration.**

If an effect does not help communicate that transformation, it probably does not belong.

## Success Criteria

Before implementation, evaluate every visual proposal against five questions:

1. Does it look meaningfully different from a conventional developer portfolio?
2. Can a recruiter understand Jet's professional identity quickly?
3. Does the artistic language reinforce the engineering narrative?
4. Does interaction reveal meaning?
5. Could half of the effects be removed while preserving the concept?

If the fifth answer is no, the design is probably relying too much on spectacle.

## Visual Validation Phase

Before implementation, generate five static concept frames:

1. Hero, ambient state
2. Hero, structured interaction state
3. Pulsar
4. RestaurantZero
5. Process

Only after those frames are approved should the final Astra implementation brief be written.

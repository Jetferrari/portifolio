01 / FLUXO DE TRABALHO

Como eu trabalho

Meu processo começa antes de qualquer código ser produzido. A implementação é apenas uma etapa dentro de um sistema maior de pesquisa, planejamento, direção, revisão por IA e validação.

01

Research

Faço uma pesquisa ampla sobre o produto, o problema, o mercado, o público e as soluções existentes antes de definir a direção.

02

Specialized Context

Crio um contexto especializado no assunto para concentrar pesquisa, raciocínio, decisões, restrições e referências relevantes para o projeto.

03

Problem Definition

Defino o problema a resolver, para quem ele existe, quais restrições importam e qual resultado final deve ser alcançado.

04

System Planning

Planejo com IA a arquitetura de alto nível, tecnologias, módulos, limites, dependências e sequência de desenvolvimento.

05

Agent Design

Crio um agente especializado para o projeto, com contexto, regras, arquitetura, objetivos e critérios de validação próprios.

06

Prompt Orchestration

O agente supervisor transforma o plano em instruções específicas para os agentes de código e analisa o retorno de cada etapa.

07

Implementation

Antigravity, Codex, Claude Code, Lovable ou Google AI Studio executam a implementação técnica.

08

Cross-Review

Sempre que necessário, utilizo uma IA diferente para revisar o trabalho produzido por outra, reduzindo dependência de um único modelo.

09

Automated Testing

Os agentes executam testes e verificações definidos para cada módulo antes de avançar.

10

Result Validation

Eu verifico se comportamento, interface, fluxos e resultados correspondem ao que foi planejado. Não aprovo código pela leitura linha por linha.

11

Iteration

Quando algo diverge do objetivo, retorno o resultado ao sistema de IA para investigação, correção, novos testes e nova validação.

02 / PROBLEM SOLVING

Problem Solving

Meu principal trabalho não é escrever código. É transformar problemas vagos em problemas solucionáveis e resultados verificáveis.

1

Entender o problema real

Separar a necessidade central de sintomas, suposições e soluções prematuras.

2

Definir o resultado

Determinar como deve se comportar o produto quando o problema estiver efetivamente resolvido.

3

Mapear restrições

Identificar recursos, limites, requisitos, dependências e condições que a solução precisa respeitar.

4

Explorar alternativas com IA

Usar pesquisa, comparação e debate com modelos para avaliar caminhos possíveis antes da implementação.

5

Planejar antes de executar

Criar contexto, estrutura, regras e critérios suficientes para reduzir improvisação durante o desenvolvimento.

6

Construir e testar

Delegar a execução técnica aos agentes e exigir verificações progressivas antes de avançar.

7

Refinar

Corrigir o que diverge do objetivo até que comportamento e experiência estejam de acordo com o planejado.

03 / PRINCÍPIOS DE ARQUITETURA

Princípios usados nos projetos

Não implemento esses padrões manualmente. Eles são utilizados como princípios e restrições durante o planejamento dos projetos. O detalhamento técnico, a implementação e a verificação ficam a cargo de agentes de IA.

Domain Driven Design

Usado para organizar o sistema em torno do domínio e das regras do produto.

Hexagonal Architecture

Usada para separar responsabilidades e reduzir dependência entre domínio, infraestrutura e interfaces externas.

Ports and Adapters

Usado como referência para definir contratos claros entre módulos e integrações.

Explicit Boundaries

Fronteiras intencionais entre módulos ajudam os agentes a manter responsabilidades separadas.

Contract Validation

Entradas e saídas são definidas com contratos que podem ser validados automaticamente.

Architecture Fitness

Verificações automatizadas podem ser usadas para avaliar se a implementação continua aderente às regras estruturais planejadas.

Idempotency

Operações sensíveis podem ser planejadas para tolerar repetições sem produzir efeitos duplicados.

Security Boundaries

Fronteiras de confiança, validação de entrada e tratamento de segredos entram como restrições desde o planejamento.

04 / AI WORKFLOW

Todo código é produzido por agentes de IA

Não escrevo código manualmente, não faço revisão linha por linha e não utilizo VS Code ou outro editor tradicional como ferramenta central de desenvolvimento. Minha função é dirigir o sistema que produz o software.

Minha validação é orientada pelo resultado

Não determino que um trecho está correto porque consigo interpretar cada linha de código. Considero uma etapa aprovada quando o software apresenta o comportamento planejado, passa pelas verificações definidas para aquela fase e entrega o resultado esperado.

Tenho especial foco em engenharia de prompts, contexto e coordenação de agentes, buscando reduzir ambiguidades, retrabalho, erros e alucinações durante a execução.
